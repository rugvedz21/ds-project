Adds emulated delay to a link, at the receiving end. It delays that peer's audio and its control traffic, so the measured RTT genuinely rises — this is a real impairment, not a cosmetic slider. Push one link to 150 ms with compensation off to hear the ensemble break apart, then switch compensation on and hear it re-lock.

A distributed computation is a partial order, not a sequence. a → b holds only if they are in the same process, or one is the send and the other the receive of the same message, or by transitivity. Two notes played on different laptops where neither heard the other are concurrent (‖) — asking which came first is not a hard question, it is a meaningless one. The Lamport scalar guarantees a → b ⟹ L(a)<L(b) but never the converse; the vector clock gives if-and-only-if, which is what makes the ‖ above detectable at all.

Names, identifiers & addresses

NameIdentifierAddress (live ICE pair)Candidate
no peers yet

Three different things, routinely confused. A name is human-readable, need not be unique and can change. An identifier is unique, immutable, and never reused — it denotes exactly one peer for that peer's whole lifetime. An address is where the peer can currently be reached, and it can change underneath a stable identifier: switch from Wi-Fi to Ethernet and the address below changes while the identifier does not. This is why every message in the system is routed by identifier and never by address.

Peers beacon each other every second over a reliable, FIFO data channel; 3.5 s of silence makes a peer suspected. If the coordinator is suspected, the Bully algorithm runs: ELECTION to every higher-ranked peer, and if none ANSWERs within 1.5 s, this node announces itself COORDINATOR. Rank is seniority — the same rule the server uses — so the two agree whenever the server is up. Kill the server and the peers still elect a coordinator, which then serialises tempo changes over the mesh.

Ricart–Agrawala, no coordinator. To solo, a node sends REQUEST(Lamport ts, id) to every peer and waits for every REPLY. A peer that holds the floor, or wants it with an older request, defers its reply until it releases. The holder plays an octave up and louder, so a violation of mutual exclusion would be audible. Press it on two laptops at once and watch one defer to the other.

A MARKER floods the reliable FIFO channels. Each node records its own state on the first marker it sees, and records every other incoming channel until that channel's marker arrives — those messages were in transit across the cut. The result is a consistent global state: one the system could have been in, though not a single instant (note the beat positions differ). Raise a link's impairment to 300 ms first to catch messages in flight.

Every control decision (join, tempo, transport, master change) is a block whose hash covers the previous block's hash. Every peer keeps a replica and verifies each block. Edit one and the chain breaks visibly — tamper-evident, not tamper-proof. One appender (the server) orders the blocks: a permissioned-ledger design, not proof-of-work consensus.

Serverless — session report UNIT 4

A stateless function (functions/session-report.js) in the Cloudflare Workers fetch() format. It is handed this replica's ledger, verifies the chain and summarises the session. The first call is a cold start; calls within 60 s reuse the warm instance; after 60 s idle it scales to zero. Tamper first, then invoke, to see it refuse the unverified suffix.

The server logs every telemetry sample to data/telemetry/<session>.jsonl. This job splits that log, runs map tasks in parallel worker threads, shuffles the (link, sample) pairs to reducers by hash, and reduces them to per-link percentiles — the questions live telemetry cannot answer. Inject failures to watch failed tasks simply re-execute: map and reduce are deterministic, so recovery needs no coordination.
